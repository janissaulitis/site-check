Why it matters
If an attacker manages to inject a script (through a comment, a plugin bug or a hacked ad), nothing stops the browser from running it. A policy limits where scripts may come from.
How to fix
Start with a report-only policy so nothing breaks, read the reports, then enforce. A safe first step that blocks plugins and framing: Content-Security-Policy: object-src 'none'; base-uri 'self'; frame-ancestors 'self'.
Netlify: add the line under /* in a _headers file.
Cloudflare: Rules → Transform Rules → Modify response header → Set static.
Nginx: add_header Content-Security-Policy "object-src 'none'; base-uri 'self'; frame-ancestors 'self'" always; in the server block.
Apache: Header always set Content-Security-Policy "object-src 'none'; base-uri 'self'; frame-ancestors 'self'" in the site config or .htaccess.
WordPress: set it at your host or CDN, or in .htaccess on Apache hosting.
